## 1. 产品概述

### 1.1 建设背景

随着公司业务、项目和客户数量增长，产品资料、实施方案、行业知识、客服口径与内部制度分散在文件服务器、个人电脑、在线文档和业务系统中。现有方式存在以下问题：

1. 知识入口分散，员工难以快速找到可信答案；
2. 同一知识存在多个版本，缺少生效范围、有效期和责任人；
3. 内容发布前缺少审核，过期知识不能及时下线；
4. 大模型回答与原始依据割裂，难以追溯；
5. 文档入库后的解析、切片、召回和生成质量缺少可视化验证；
6. 测试知识与生产知识边界不清，存在未经验证内容进入正式应用的风险。

因此建设“星途-RAG 知识库平台”，将企业知识转化为可治理、可检索、可评测、可审计、可复用的智能资产，并为智能客服、员工助手、项目助手、销售助手等智能产品提供统一知识底座。

### 1.2 产品定位

星途-RAG 知识库平台是位于企业内容源与 AI 应用之间的知识治理与 RAG 运营中台。

- 平台负责：知识库、文档、版本、审核、权限、入库任务、处理验收、检索调试、评测、发布和运营分析；
- RAG 引擎负责：解析、切片、向量化、索引、召回、重排及基于知识的答案生成；
- 智能应用负责：面向最终用户提供对话体验、业务流程与实时系统能力。

平台通过标准适配层对接 FastGPT、Dify、自研 RAG 服务或其他引擎，不与单一供应商深度绑定。

### 1.3 产品愿景

让公司每一项有效知识都“有来源、有版本、有负责人、可验证、可追溯”，让每一次 AI 回答都建立在可信知识之上。

### 1.4 建设目标

#### 业务目标

- 统一管理企业知识资产，降低搜索和重复整理成本；
- 建立知识审核、发布和失效机制，保障业务口径一致；
- 支撑多个智能产品快速复用同一知识能力；
- 通过问题案例闭环持续发现知识缺口。

#### 体验目标

- 非技术运营人员可独立完成上传、审核、发布和效果检查；
- 关键状态、待办和风险在一个工作台内清晰呈现；
- 检索结果必须展示文档、章节、版本和相关度；
- 失败任务提供可理解的原因和可执行的下一步。

#### 质量目标

- 正式答案具备有效引用，可回溯至原文；
- 未命中有效知识时明确兜底，不生成无依据业务结论；
- 测试与生产资源严格隔离；
- 高风险知识在未通过审核和评测前不得发布。

### 1.5 版本范围

V1.0 聚焦知识治理闭环，不建设复杂的模型训练平台、通用工作流编排器和实时业务数据中心。

范围内：

- 知识库与文档版本管理；
- 文件上传及数据源接入；
- 业务审核、RAG 处理与人工验收；
- 检索调试、批量评测与发布审批；
- 问题案例、权限审计和运营统计；
- 多 RAG 引擎配置及测试/生产资源映射。

范围外：

- 自研 OCR、Embedding、向量数据库和大模型；
- 替代 OA 的完整审批中心；
- 替代缺陷系统的研发工单管理；
- 订单、库存、客户账户等实时数据存储；
- 面向终端用户的完整智能客服界面。

## 2. 用户与场景

### 2.1 用户角色

#### 知识运营

负责知识库创建、资料整理、文档上传、元数据维护、处理结果验收、检索调试和知识生命周期管理。

#### 业务审核人

负责确认内容事实、适用范围、风险等级和正式业务口径；不能审核自己提交的高风险内容。

#### AI 产品经理 / 测试人员

负责维护评测集、执行冒烟测试和全量回归、判断发布门槛是否满足。

#### 应用负责人

负责将已发布知识接入智能客服、员工助手等应用，并反馈线上效果。

#### 系统管理员

负责组织、成员、角色、数据权限、引擎连接、密钥和审计日志。

#### 只读审计员

可查看版本、审批、评测、发布和操作证据，但不能修改业务数据。

### 2.2 核心使用场景

1. 知识运营创建“产品资料库”，上传产品手册并填写版本、负责人和有效期；
2. 业务审核人核对新旧版本差异，对高风险条款进行审核；
3. 审核通过后，平台自动将文档推送至测试环境；
4. 知识运营检查解析正文、切片、索引数量和异常；
5. 测试人员运行真实问题，检查召回证据和最终回答；
6. 达到评测门槛后发起发布审批，批准后同步至生产环境；
7. 智能应用调用生产知识，答案展示有效引用；
8. 线上异常自动或人工沉淀为问题案例，修复后重新走验证流程。

- 员工知识助手
- 项目交付助手
- 销售支持助手
- 文档问答

#### 星途知识治理层

- 知识库与目录
- 文档与版本
- 审核与发布
- 数据权限
- 入库任务
- 检索调试
- 批量评测
- 运营统计
- 开放 API

#### RAG 能力层

- 文档解析
- OCR 与表格识别
- Chunk 切分
- Embedding
- 向量索引
- 混合检索
- Rerank
- 大模型生成

#### 基础设施层

- 对象存储
- 关系型数据库
- 日志与监控
- 统一身份认证
- 密钥管理

### 3.2 数据边界

- 权威文档、标准 FAQ：审核与评测通过后可进入生产索引；
- 历史对话、工单、问题反馈：仅用于提取候选知识和评测问题，不能直接成为正式答案；
- 订单、库存、物流、账户等实时数据：由智能应用运行时调用业务 API，不能写入知识向量库；
- 含个人信息或敏感信息的资料：必须完成脱敏、授权和访问控制后才能处理。

### 3.3 核心原则

1. 测试与生产知识物理或逻辑隔离；
2. 业务版本与 RAG 资源 ID 建立一一可追溯映射；
3. 审核内容正确性、验收加工正确性、评测答案正确性相互独立；
4. 新版本发布不覆盖历史记录；
5. 所有关键动作可审计；
6. 浏览器不直接持有 RAG 引擎密钥。

## 5. 核心业务流程

### 5.1 主流程

创建知识库 → 上传文档 → 保存草稿 → 提交审核 → 业务审核 → 测试环境入库 → 处理结果验收 → 检索验证 → 批量评测 → 发布审批 → 生产环境发布 → 应用调用 → 运营反馈。

### 5.2 文档状态机

- **草稿**：可编辑、删除或提交审核；
- **待审核**：内容锁定，等待业务审核；
- **已驳回**：退回提交人修改；
- **测试入库中**：RAG 引擎正在处理；
- **待验收**：等待检查解析和切片结果；
- **待检索验证**：处理已验收，等待召回验证；
- **待批量评测**：检索通过，等待答案质量评测；
- **待发布审批**：评测达标，等待最终审批；
- **生产发布中**：正在同步生产资源；
- **已发布**：可供正式应用检索；
- **发布失败**：生产同步异常，可重试；
- **已下线**：不再参与生产检索；
- **已归档**：仅保留历史记录。

### 5.3 版本规则

- 任何已提交审核或已发布版本不可直接修改；
- 修改已发布知识必须创建新版本；
- 每个版本记录原文件、正文快照、元数据、审核、RAG 参数、资源 ID、评测结果和发布记录；
- 新版本发布成功后，旧版本停止参与生产召回，但保留审计记录；
- 到达有效期的版本自动进入“待下线”预警，经确认后下线。

### 5.4 发布门槛

必须同时满足：

1. 业务审核通过；
2. 文档解析完整、切片合理、索引数量一致；
3. 指定检索问题的正确知识进入 Top K；
4. P0 安全用例失败数为 0；
5. 核心用例通过率达到配置阈值；
6. 阻断级问题案例全部关闭；
7. 发布审批通过；
8. 目标生产资源与测试资源不相同。

## 6. 功能需求

### F-01 运营总览（P0）

#### 页面目标

让用户快速判断知识运营是否健康，以及今天优先处理什么。

#### 功能要求

- 展示知识库数、已发布文档数、待审核数、处理中任务数、评测通过率和开放问题数；
- 展示“待我处理”列表，按风险和超时时间排序；
- 展示从草稿到发布的流程漏斗；
- 展示知识健康度、近 30 天问答趋势和高频未命中问题；
- 支持按组织、业务域、知识库和时间范围筛选；
- 不同角色只展示其有权限的数据和待办。

### F-02 知识库管理（P0）

#### 功能要求

- 新建、编辑、搜索、筛选、停用和归档知识库；
- 字段包括名称、编码、描述、业务域、负责人、可见范围、风险等级、标签；
- 配置测试/生产 RAG 资源映射；
- 展示文档数、已发布数、健康度和更新时间；
- 支持成员级、部门级、角色级数据授权；
- 删除有历史版本或生产引用的知识库时必须禁止物理删除。

### F-03 文档与版本（P0）

#### 支持类型

PDF、DOCX、PPTX、XLSX、TXT、Markdown、HTML、CSV、结构化 FAQ。

#### 功能要求

- 单文件上传、批量上传、拖拽上传；
- 展示文件格式、大小、校验值和上传人；
- 维护标题、知识类型、分类、标签、渠道、地区、语言、负责人、有效期和风险等级；
- 自动检查必填项、重复文件、空文件和不支持格式；
- 展示版本时间线、版本差异及每次变更说明；
- 支持预览原文、下载原文件、创建新版本、下线和归档；
- 支持按标题、编号、标签、状态、负责人和有效期筛选。

### F-04 数据源（P1）

- 支持连接文件目录、在线文档、CMS、对象存储和标准 API；
- 配置同步范围、周期、字段映射、冲突策略和删除策略；
- 首次同步必须以预览模式展示影响范围；
- 同步形成新版本，不得覆盖已发布版本；
- 记录每次同步的新增、更新、跳过和失败数量。

### F-05 业务审核（P0）

- 展示待审核列表、风险等级、提交人和等待时长；
- 左右对比线上版本与待审版本；
- 高亮新增、修改和删除内容；
- 审核人必须确认来源可信、适用范围准确、高风险口径明确；
- 支持通过、驳回、转交和添加意见；
- 驳回原因必填；
- 高风险知识支持多人会签；
- 防止提交人与审核人是同一人。

### F-06 入库任务（P0）

- 自动为审核通过版本创建测试入库任务；
- 展示平台任务 ID、外部任务 ID、环境、步骤、进度和状态；
- 记录解析器、切片策略、Embedding、索引与 Rerank 配置快照；
- 支持手动推送、状态刷新、失败重试和取消；
- 使用幂等键防止同一版本重复入库；
- 回调验签并记录原始响应摘要；
- 超时、失败和数量不一致时触发告警。

### F-07 处理结果验收（P0）

- 展示解析页数、字符数、标题数、表格数和异常数；
- 展示 Chunk 列表、章节路径、Token 数、原文定位和可索引状态；
- 校验有效 Chunk 数、向量数和索引数；
- 支持搜索、筛选和抽样查看；
- 支持“验收通过”和“退回重处理”；
- 退回时必须选择原因，可修改切片参数后创建新任务；
- 原型中提供原文与切片的联动预览。

### F-08 检索调试（P0）

- 输入真实问题，选择知识库、环境、Top K、检索模式和过滤条件；
- 展示召回片段、相关度、重排分数、文档、版本、章节和命中原因；
- 支持向量、关键词和混合检索；
- 支持查看生成答案及引用；
- 支持将某片段标记为预期结果；
- 支持“确认通过”或“标记问题”；
- 保存每次运行的参数和结果快照，便于复现。

### F-09 批量评测与发布（P0）

#### 评测阶段

1. 冒烟评测：覆盖核心链路与 P0 安全问题；
2. 正式评测：覆盖当前版本主要业务问题；
3. 全量回归：验证新版本是否破坏已有能力；
4. 场景验证：在真实多轮对话中人工确认体验。

#### 功能要求

- 支持 XLSX/CSV 导入评测集；
- 评测项包含问题、标准答案、预期来源、风险等级、标签；
- 展示引用命中、答案一致性、完整性、忠实度和延迟；
- 支持人工复核模型评分；
- 失败项自动生成问题案例；
- 发布页实时计算门槛并说明阻断原因；
- 发布必须记录审批人、发布说明和回滚版本；
- 生产同步失败时保留旧版可用，不得产生半发布状态。

### F-10 问题案例（P0）

- 来源包括检索调试、批量评测、场景验证和线上反馈；
- 展示问题摘要、来源、风险、知识库、责任人、状态和发生时间；
- 详情保留问题、回答、引用、运行参数和版本证据；
- 状态：待分派、处理中、待验证、已关闭；
- 支持绑定修复版本和责任人；
- 修复完成后必须回放原问题；
- 同类问题再次出现时创建新记录，不覆盖旧证据。

### F-11 权限与审计（P0）

- 支持组织、角色和知识库数据范围授权；
- 权限粒度覆盖查看、编辑、审核、评测、发布、配置和导出；
- API 密钥只显示一次，支持过期、轮换、禁用和 IP 白名单；
- 审计日志记录时间、用户、动作、对象、结果、IP 和变更前后摘要；
- 关键日志不可由普通管理员删除；
- 支持按时间、人员、资源和动作查询与导出。

### F-12 RAG 引擎配置（P0）

- 支持 FastGPT、Dify、自研服务和标准适配器；
- 配置服务地址、鉴权方式、超时、重试和回调密钥；
- 分别配置测试与生产资源；
- 提供连接测试和权限校验；
- 敏感字段加密存储，页面仅展示掩码；
- 切换 Provider 时保留历史配置快照；
- 引擎不可用时不得影响平台内已有文档和审计记录查看。

### F-13 开放能力（P1）

- 提供知识检索、问答、引用详情和反馈接口；
- 提供发布、下线、任务状态等事件回调；
- 支持租户、应用和知识库级限流；
- 返回 traceId 以关联平台日志与应用日志；
- API 只允许访问已授权的生产知识；
- 提供 SDK 示例和接口调试页。

## 7. 页面交互规范

### 7.1 全局框架

- 左侧为分组导航，顶部展示当前页面、全局搜索、环境状态和用户；
- 主内容区采用卡片、表格、状态标签和侧滑详情；
- 重要创建动作使用主色按钮；
- 危险动作使用红色并进行二次确认；
- 页面记住最近一次筛选条件，但不跨账号共享。

### 7.2 状态反馈

- 2 秒内完成的操作使用 Toast；
- 超过 2 秒的任务进入任务中心，不使用阻塞式加载；
- 空状态说明原因并提供下一步；
- 错误信息包括发生位置、可理解原因、建议动作和 traceId；
- 无权限时隐藏不可用入口或给出明确权限说明。

### 7.3 无障碍与适配

- 桌面端优先，最低支持 1280×720；
- 关键页面在平板宽度下可用；
- 颜色不是唯一状态表达，同时显示文字或图标；
- 表单控件有标签，键盘可完成主要操作；
- 正文与背景对比度满足 WCAG 2.1 AA 基本要求。

## 9. 非功能需求

### 9.1 性能

- 常规列表首屏 P95 小于 2 秒；
- 10 万文档规模下搜索 P95 小于 3 秒；
- 单次支持上传 2 GB 文件，具体阈值可配置；
- 批量评测采用异步任务，支持至少 10 个并行任务；
- 检索 API 可用性目标不低于 99.9%。

### 9.2 安全

- 接入公司 SSO，支持 MFA；
- 服务端统一管理外部引擎凭证；
- 传输使用 TLS，敏感配置加密存储；
- 防止越权检索、提示词注入、恶意文件和敏感信息泄露；
- 上传文件进行类型、大小、病毒和内容安全检查；
- 生产发布、密钥操作和权限变更必须审计；
- 数据保留和删除遵循公司安全制度。

### 9.3 可靠性

- 任务提交具备幂等性；
- 外部引擎调用使用指数退避重试和熔断；
- 回调失败可补偿查询；
- 发布过程支持原子切换和快速回滚；
- 关键元数据每日备份，定期进行恢复演练。

### 9.4 可观测性

- 统一采集任务成功率、耗时、错误码、检索延迟和模型消耗；
- 日志通过 `traceId` 串联应用、平台和 RAG 引擎；
- 支持连接异常、任务积压、评测下降和生产发布失败告警。

### 11.1 平台调用 RAG 引擎

- 创建/更新测试知识资源；
- 提交文件或结构化内容；

- `GET /v1/citations/{id}`：获取引用详情；

- `GET /v1/health`：检查服务状态。

正式接口需另行定义鉴权、字段、错误码、分页、限流、幂等和签名规范。

## 12. 验收标准

### 12.1 主流程验收

1. 可创建知识库并完成授权；
2. 可上传文档、保存元数据并提交审核；
3. 审核通过后自动创建测试入库任务；
4. 可查看处理进度、解析结果与 Chunk；
5. 验收通过后可执行检索和批量评测；
6. 不满足门槛时发布按钮不可用并说明原因；
7. 审批和评测满足条件后可发布生产；
8. 新版本发布后旧版本停止参与生产检索；
9. 智能应用可获取带有效引用的答案；
10. 全流程关键操作可在审计日志中查询。

### 12.2 异常验收

- 重复提交不会创建重复任务；
- 外部引擎不可用时提示可理解且可重试；
- 回调重复到达不会重复改变状态；
- 生产发布失败不影响当前线上版本；
- 越权用户无法查看文档正文和检索结果；
- 过期知识不会继续参与生产问答；
- 高风险评测失败时无法绕过门槛发布。

## 14. 风险与对策

- **知识责任不清**：没有负责人和有效期的知识不得发布；
- **历史资料污染**：历史对话仅作为样本，不直接入生产；
- **引擎厂商锁定**：通过 Provider Adapter 隔离业务层与引擎差异；
- **模型幻觉**：强制引用、无知识兜底、高风险测试和答案忠实度评测；
- **权限泄露**：检索前执行数据权限过滤，服务端保管密钥；
- **评测失真**：评测集覆盖真实问法并定期抽样复核；
- **发布中断**：生产资源采用版本化和原子切换，保留回滚点；
- **运营流于形式**：把审核、验收、评测门槛固化为系统状态机。
