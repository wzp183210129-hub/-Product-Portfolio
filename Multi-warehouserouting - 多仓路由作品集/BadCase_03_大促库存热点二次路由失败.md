| **严重等级** | P2（时效降级，无错发/丢单） |
| **复盘人** | wzp |

## 1. 事件概述

双 11 零点秒杀开场，00:00~00:10 路由请求峰值达 **12,000 次/分钟**（日常 200 次/分钟）。部分订单的路由推荐在 00:03 生成（推荐广州仓 WH-GZ-001），但 WMS 在 00:08 执行发货前二次校验时发现 SKU-002 库存已被其他订单消耗，触发重新推荐。

由于广州仓、武汉仓同时缺货 SKU-002，186 单退回人工处理队列，平均延迟 3 小时才发出。

---

## 2. 时间线

| 时间 | 事件 |
|------|------|
| 00:00 | 秒杀开始，路由 QPS 飙升 |
| 00:03 | 订单 A 路由推荐广州仓（SKU-002 库存 50） |
| 00:05~00:07 | 同期 200+ 单同样推荐广州仓 SKU-002 |
| 00:08 | 订单 A 发货前校验：SKU-002 库存 0，二次路由失败 |
| 00:10 | 186 单进入「路由失败-人工队列」 |
| 00:15 | 运营介入，手动指定成都仓 / 拆单发货 |
| 00:45 | 186 单全部处理完毕 |

---

## 3. 根因分析

### 3.1 技术根因

| 层级 | 问题 |
|------|------|
| 库存 | 路由计算读的是**缓存库存**（Redis，TTL 30s），非实时扣减 |
| 并发 | 高并发下 30s 缓存窗口内，多单基于同一库存快照做推荐 |
| 二次校验 | 有二次校验机制，但**次近仓同样缺货**时无自动拆单/候补逻辑 |
| 队列 | 异步队列 10s 超时，部分请求在 00:02~00:05 积压 |

### 3.2 产品根因
- PRD 中「大促降级」只考虑了**负载 >80% 跳过**，未考虑**库存热点 SKU 超卖**
- 路由失败后的**降级路径**不清晰：退回人工是唯一出口

---

## 4. 影响评估

| 维度 | 影响 |
|------|------|
| 订单 | 186 / 约 45,000 单（0.4%） |
| 时效 | 延迟 2~4 小时，未超 24h 承诺 |
| 客诉 | 2 起催发货，无赔偿 |
| 成本 | 部分改从成都仓发，成本略增 ¥1.2/单 |

---

## 5. 改进措施

| 措施 | 优先级 | 状态 | 说明 |
|------|--------|------|------|
| 大促前热点 SKU 库存**路由级预扣**（推荐时锁库存 60s） | P0 | ✅ 12月完成 | 推荐到发货窗口内预留 |
| 二次路由失败 → 自动**拆单**（有货 SKU 先发） | P0 | ✅ 12月完成 | 减少整单卡住 |
| 路由缓存 TTL 大促期间从 30s 降至 **5s** | P1 | ✅ | 降低快照偏差 |
| 人工队列 SLA 告警（>50 单 / 5min 推送） | P1 | ✅ | 运营及时介入 |
| 二期：销量预测 + 大促前**预调拨** | P2 | 📋 规划中 | 从源头减少缺货 |

---

## 6. 经验沉淀

### 做对的
- **发货前二次校验**避免了错发（没从缺货仓发出）
- 异步队列扛住了 12,000 次/分钟峰值，无丢单

### 待改进
- 大促方案不能只有「负载降级」，还要考虑**库存热点**
- 路由失败不能只有「退回人工」，要有**拆单、候补仓、预扣**多级降级

### 面试话术
> 「双 11 开场 40 分钟，186 单因为热点 SKU 库存被抢导致二次路由失败。根因是路由读缓存库存，高并发下多单基于同一快照推荐。我们加了路由级预扣和自动拆单，大促再没出现整单卡住的情况。」
