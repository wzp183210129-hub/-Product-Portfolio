## 3. V1.0 能力选型详情

### 3.1 地址解析（NLP + 地理编码）

| 维度 | 内容 |
|------|------|
| **业务需求** | 将「广东省广州市天河区体育西路 xx 号」转为经纬度，供距离计算 |
| **候选方案** | A. 正则 + 词典匹配  B. 高德/百度地理编码 API  C. 自研 NLP 地址解析模型 |
| **选型** | **B. 高德地理编码 API（主） + A. 词典兜底（辅）** |
| **理由** | ① 准确率 98%+，省自研成本 ② 模糊地址有市级坐标兜底 ③ API 按量计费，日均 15 万单约 ¥450/天 |
| **不选 C 的原因** | 地址解析是成熟能力，自研 ROI 低；团队无 NLP 工程资源 |
| **兜底策略** | API 失败 → 词典提取省市区 → 市级行政中心坐标 |

### 3.2 距离计算

| 维度 | 内容 |
|------|------|
| **业务需求** | 计算仓库坐标 ↔ 收件坐标之间的距离，用于排序 |
| **候选方案** | A. 直线距离（Haversine）  B. 驾车路径距离（API）  C. 预计算距离矩阵 |
| **选型** | **A. Haversine 直线距离** |
| **理由** | ① 5 仓场景下排序结果与驾车距离 95% 一致 ② 计算 <1ms，无 API 依赖 ③ 大促无额外成本 |
| **不选 B 的原因** | 15 万单 × 5 仓 = 75 万次路径 API/天，成本高且延迟大 |
| **不选 C 的原因** | 5 仓 × 300 地级市 = 1500 条，矩阵维护成本 > 实时计算 |

### 3.3 异常检测（健康巡检）

| 维度 | 内容 |
|------|------|
| **业务需求** | 自动发现灰度超期、有货未配路由、跨仓占比异常 |
| **候选方案** | A. 固定阈值规则  B. 统计异常检测（Z-Score/IQR）  C. 时序预测模型 |
| **选型** | **A. 固定阈值（主） + B. Z-Score 环比检测（辅）** |
| **理由** | ① 3 类巡检场景边界清晰，规则可解释 ② 跨仓占比用 Z-Score 检测突增，减少误报 ③ 运营需要知道「为什么告警」，黑盒模型不适合 |
| **阈值配置** | 灰度 >30 天、跨仓占比周环比 >5pp、库存 >100 且路由未启用 |

### 3.4 路由核心：规则引擎 vs ML 模型

| 维度 | 内容 |
|------|------|
| **业务需求** | 给定订单，推荐最优发货仓 |
| **候选方案** | A. 规则引擎（库存过滤 + 距离排序）  B. 机器学习排序模型  C. 强化学习动态路由 |
| **选型** | **A. 规则引擎** |
| **理由** | ① 78% 跨仓是「附近有货但路由错了」，规则直接解决 ② 5 仓场景组合空间有限，ML 无显著增益 ③ 规则可解释、可 debug、运营可信任 |
| **不选 B/C 的原因** | 缺训练数据（历史无路由决策日志）；负载数据不准，特征质量差 |

## 4. V1.1 规划能力

### 4.1 AI 推荐理由生成

| 维度 | 内容 |
|------|------|
| **需求** | 向运营展示「为什么推荐广州仓」的自然语言说明 |
| **方案** | 结构化模板 + 轻量 LLM 润色（星途内部 GPT-4o-mini 级模型） |
| **示例** | 输入：`{rec: 广州仓, dist: 8km, stock: ok, load: 45%}` → 输出：「推荐广州仓：距收件地址仅 8 公里，全量 SKU 有货，仓内负载 45% 正常。」 |
| **成本** | ~500 tokens/单，日均人工查看约 2000 单，月成本 <¥200 |

### 4.2 配置漂移检测

| 维度 | 内容 |
|------|------|
| **需求** | 检测灰度比例等配置被误改（Bad Case #01 教训） |
| **方案** | 配置快照 diff + 变更频率异常检测 |
| **触发** | 1h 内灰度比例变化 >20% → 企业微信告警 |

## 7. 选型原则总结

| 原则 | 说明 | 案例 |
|------|------|------|
| **确定性优先** | 能规则就不 ML | 路由排序用距离，不用排序模型 |
| **买而不造** | 成熟能力用 API | 地址解析用高德，不自研 NLP |
| **可解释性** | 运营要能理解和 debug | 健康巡检用阈值 + Z-Score |
| **分期演进** | 数据够了再上 ML | 负载准确后再加多目标优化 |
| **成本可控** | AI 成本 < 节省价值的 5% | 月 AI 成本 ¥1.3 万 vs 节省 ¥180 万 |

## 8. 风险与应对

| 风险 | 应对 |
|------|------|
| 地理编码 API 不可用 | 词典兜底 + 市级坐标 |
| 地址解析准确率不足 | 用户收货地址标准化（前端引导） |
| 规则引擎无法覆盖复杂场景 | V1.1 加推荐理由 + 人工覆盖；V2.0 上 ML |
| AI 成本超预期 | 缓存解析结果（同地址 24h 内复用） |
