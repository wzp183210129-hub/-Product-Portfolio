## 2. 产品概述

### 2.1 产品定位

**星途AI-多仓路由** 是星途时动面向平台电商 / DTC 品牌的智能仓储履约产品。在订单支付后，基于 AI 地址解析、距离计算与库存过滤，自动推荐最优发货仓，并提供规则配置、健康巡检与运营干预能力。

**一句话定位：** 让每一单都从「最近的有货仓」发出，而不是被 3 年前的静态路由表绑死。

### 2.2 目标用户

| 角色 | 核心诉求 |
|------|----------|
| 仓储运营 | 订单进来后系统自动推荐最近有货仓，减少逐单改仓 |
| 物流专员 | 换仓后自动通知承运商变更揽收点 |
| 运营主管 | 看跨仓占比、履约时效趋势，量化路由优化价值 |
| 仓储规划 | 新仓上线后快速配置覆盖区域与灰度策略 |

### 2.3 业务背景

某运动户外 DTC 平台日均订单 15 万，2025 年由北京、长沙 2 仓扩至广州、成都、武汉等 5 仓。系统仍按旧的「省份→仓库」静态规则分配，导致：

- **跨仓发货占比 40%**：近四成订单收件地址离下单仓超过 500 km
- **平均履约时效 3.5 天**：跨省快递耗时远超同城 1 天可达
- **单均物流成本 ¥8.6**：跨区快递均价比同城高 40%

**根因：** 不是没做路由，而是 2 仓时代的路由规则没有跟上 5 仓网络扩张——运营债务被忽视。

### 2.4 产品目标

| 指标 | 优化前 | 目标值 | 衡量周期 |
|------|--------|--------|----------|
| 跨仓发货占比 | 40% | ≤15% | 全量上线后 4 周 |
| 平均履约时效 | 3.5 天 | ≤2.3 天 | 全量上线后 4 周 |
| 单均物流成本 | ¥8.6 | ≤¥6.8 | 全量上线后 4 周 |
| 运营人工干预率 | — | <5% | 持续监控 |
| 路由推荐响应时间 | — | P99 ≤500ms | 上线即监控 |

## 3. 用户故事与场景

### 3.1 核心用户故事

| 角色 | 我希望… | 以便… |
|------|---------|-------|
| 仓储运营 | 订单支付后系统自动推荐最近有货仓 | 减少跨区发货，降低包裹在途时间 |
| 物流专员 | 发货仓变更后自动通知承运商换仓揽收 | 不用手工通知快递改地址 |
| 运营主管 | 看板展示跨仓占比和履约时效趋势 | 有数据向管理层汇报优化成果 |
| 仓储规划 | 新仓上线可配置覆盖区域并灰度试跑 | 安全接入路由网络，避免一刀切 |

### 3.2 典型场景

**场景 A：舍近求远（主场景）**

> 买家在广东广州下单，OMS 分配北京仓（WH-BJ-002）。支付后星途AI 解析收件地址，发现广州仓（WH-GZ-001）距收件地 8 km 且全量有货，推荐切换。运营确认后，预计节省 2100 km、约 2.5 天履约时间。

**场景 B：新仓灰度试跑**

> 武汉仓新上线，仓储规划配置覆盖湖北/河南/江西，路由状态设为「灰度运行（10% 流量）」。试跑 30 天后健康监控提醒转正，运营主管一键切至全量。

**场景 C：有库存但未配路由**

> 上海仓库存充足，但覆盖区域未配置、路由状态为「未启用」。健康巡检自动标记，推送企业微信提醒仓储规划去配置，避免华东订单继续跨区发货。

## 4. 功能需求

### 4.1 功能架构

```
星途AI-多仓路由
├── 路由推荐（核心）
│   ├── 订单信息展示
│   ├── AI 推荐结果与理由
│   ├── 候选仓对比表
│   └── 人工干预（确认/保持/手动指定）
├── 规则配置
│   ├── 仓库覆盖区域管理
│   ├── 路由状态（未启用/灰度/全量）
│   └── 操作日志与版本回滚
└── 健康监控
    ├── 巡检仪表盘
    ├── 异常告警与处置
    └── 自动巡检规则配置
```

### 4.2 模块一：路由推荐

#### 4.2.1 订单信息卡片

| 字段 | 说明 | 必填 |
|------|------|------|
| 订单号 | OMS 订单唯一标识 | 是 |
| 下单时间 | 支付完成时间 | 是 |
| 收件地址 | 完整收货地址 | 是 |
| 下单仓 | OMS 初始分配仓 + 标签 | 是 |
| SKU 数 / 总件数 | 订单商品汇总 | 是 |
| 下单仓发货距离 | 下单仓至收件地址直线距离，跨区时警告展示 | 是 |

#### 4.2.2 AI 推荐结果

- 展示推荐仓名称、距离、库存状态、预计履约时效
- 展示相比下单仓节省的距离与时间
- **AI 推荐理由**（V1.0）：结构化展示「全量有货 + 距离最近 + 负载正常」

#### 4.2.3 候选仓库对比表

| 列 | 说明 |
|----|------|
| 仓库 | 仓名 + 仓 ID + 标签（推荐/下单仓） |
| 距离 | 至收件地址直线距离（km） |
| 全量库存 | ✅ 充足 / ⚠ 缺货 SKU |
| 负载 | 仓内作业负载百分比 |
| 路由状态 | 全量 / 灰度 / 未启用 |
| 操作 | 预留扩展 |

**排序规则：** 按距离升序；已过滤缺货仓与未启用路由仓。

#### 4.2.4 操作按钮

| 按钮 | 行为 | 备注 |
|------|------|------|
| 确认切换至推荐仓 | 写入路由结果，通知 WMS + 承运商 | 主路径 |
| 保持原下单仓 | 记录决策原因，按原仓发货 | 需留痕 |
| 手动指定仓库 | 弹窗选择全量有货仓，覆盖推荐 | 运营兜底 |

### 4.3 模块二：规则配置

#### 4.3.1 仓库卡片

每个仓库展示：
- 仓名、仓 ID
- 路由状态：未启用 / 灰度运行（10% 流量）/ 全量运行
- 覆盖区域：省份 Chip 列表，支持增删
- 最后修改人与时间

#### 4.3.2 路由状态流转

```
未启用 → 灰度运行（10%） → 全量运行
   ↑           ↓                ↓
   └──────── 关闭路由 ←──────────┘
```

**约束：**
- 新仓默认「未启用」，须先配置覆盖区域
- 状态变更即时生效，写入操作日志
- 关闭路由需二次确认

#### 4.3.3 覆盖区域管理

- 支持按省份添加/移除
- 同一省份不可被多仓重复覆盖（冲突时提示）
- 变更即时生效

### 4.4 模块三：健康监控

#### 4.4.1 仪表盘指标

| 指标 | 说明 |
|------|------|
| 已接入仓库数 | 系统中全部仓库 |
| 灰度运行超期 | 灰度状态超过 30 天的仓数 |
| 未启用路由的仓库 | 有库存但未参与路由的仓数 |
| 本周跨仓发货占比 | 环比趋势 |

#### 4.4.2 自动巡检项

| 巡检项目 | 触发条件 | 通知对象 |
|----------|----------|----------|
| 灰度运行超期提醒 | 灰度状态 >30 天 | 运营主管（企业微信） |
| 仓库未启用路由检测 | 有库存但路由未启用或覆盖为空 | 运营主管 + 仓储规划 |
| 跨仓占比异常预警 | 周环比升高 >5 个百分点 | 运营主管 |
| 路由配置变更留痕 | 每次修改状态或覆盖区域 | 操作日志 |

#### 4.4.3 告警处置动作

- 转为全量运行
- 已知悉，延后处理
- 关闭该仓路由
- 跳转至规则配置页

## 5. 路由算法与 AI 能力

### 5.1 推荐规则（优先级）

| 优先级 | 规则 | 说明 |
|--------|------|------|
| 1 | 路由状态过滤 | 剔除「未启用」仓；灰度仓仅承接配置比例流量 |
| 2 | 全量 SKU 有货 | 剔除任一 SKU 缺货的仓 |
| 3 | 距离最近 | 对剩余仓按直线距离升序 |
| 4 | 同距离保下单仓 | 减少换仓成本 |
| 5 | 大促负载降级 | 最近仓负载 >80% 时跳过，选次近仓 |

### 5.2 AI 能力接入（详见《AI 能力选型说明》）

| 能力 | 用途 | V1.0 |
|------|------|------|
| 地址解析（NLP + 地理编码） | 收件地址 → 经纬度 | ✅ |
| 距离计算 | 仓坐标 ↔ 收件坐标 Haversine | ✅ |
| 异常检测 | 健康巡检阈值与趋势告警 | ✅ |
| 推荐理由生成 | 结构化模板 + 轻量 LLM 润色 | 可选 |
| 销量预测 + 预调拨 | 大促前备货 | ❌ 二期 |

### 5.3 极端情况兜底

| 场景 | 处理方式 |
|------|----------|
| 所有仓缺货 | 退回下单仓发货 |
| 推荐后库存被抢 | WMS 二次校验，不足则取次近仓 |
| 地址解析失败 | 取市级行政中心坐标兜底 |
| 大促峰值 >8000 次/小时 | 异步队列，10 秒内返回 |

## 8. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 路由推荐 P99 ≤500ms；峰值 10000 次/小时队列不丢不重 |
| 可用性 | 路由服务 SLA 99.9%；降级开关可秒级回滚 |
| 安全 | 操作日志不可篡改；人工覆盖需记录 reason |
| 兼容性 | 不影响 OMS 下单主流程；WMS 发货环节增量接入 |

## 10. 验收标准

| 验收项 | 标准 | 验证方式 |
|--------|------|----------|
| 推荐准确性 | 100% 满足全量有货 + 距离最近 | 50 单造数逐单验证 |
| 库存二次校验 | 不足自动切次近仓 | 模拟库存被抢 |
| 人工覆盖 | 可指定发货仓并留痕 | 操作验证 |
| 地址兜底 | 模糊地址用市级坐标 | 输入模糊地址测试 |
| 大促峰值 | 10000 次/小时队列完整 | 压测 |
| 健康巡检 | 3 类告警正常触发与推送 | 配置触发条件验证 |
| 成本统计 | 路由前后成本对比误差 <1% | 对比 2 周物流账单 |

## 11. 范围边界（Out of Scope · V1.0）

- ❌ 下单时锁定最优仓（支付后才路由）
- ❌ 三维加权（距离×库存×负载），负载数据不准暂不接
- ❌ 预售下沉 / 销量预测预调拨
- ❌ 全自动零人工（保留运营手动指定）
- ❌ 承运商 TMS 深度集成（V1.0 仅通知换仓揽收）
