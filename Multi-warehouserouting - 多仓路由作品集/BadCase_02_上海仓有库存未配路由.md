## 1. 事件概述

上海仓（WH-SH-006）于 2026-04-20 完成 WMS 对接并入库，库存可满足约 85% 华东订单。但仓储规划部未完成「覆盖区域配置」和「路由状态开启」，系统健康巡检于 6 月 15 日首次扫描时发现：**上海仓库存充足，路由状态为「未启用」，覆盖区域为空**。

这意味着 56 天内，所有华东买家订单仍从北京仓（2100 km）或长沙仓（1100 km）发出。

---

## 2. 量化影响

| 指标 | 数值（56 天估算） |
|------|-------------------|
| 受影响订单 | ~24,000 单 |
| 多走平均距离 | ~1,400 km/单 |
| 额外物流成本 | ~¥115,200（按 ¥0.004/km·kg 估算） |
| 平均多等时效 | ~1.8 天/单 |
| 潜在客诉 | 3 起「为什么从上海买要从北京发」 |

---

## 3. 根因分析

### 3.1 直接原因
新仓上线 SOP 中，WMS 对接完成后**没有强制卡点**「路由配置完成」才能接订单。

### 3.2 组织原因
| 角色 | 问题 |
|------|------|
| 仓储规划 | 上海仓团队 focus 在人员和设备，认为「有库存就能卖」 |
| 运营 | 不知道新仓不在路由候选池，以为系统自动会分 |
| PM（wzp） | 产品上线时未将「路由配置」纳入新仓上线 Checklist |

### 3.3 系统原因
- 新仓默认「未启用」是正确的设计，但**缺少主动阻断**：库存可售但路由未配时应告警而非静默
- 健康巡检 V1.0 尚未上线，6 月 15 日才首次扫描到

## 4. 处置过程

| 时间 | 动作 |
|------|------|
| 06-15 08:00 | 健康巡检标记上海仓，推送企业微信 |
| 06-15 10:30 | wzp 召集仓储规划 + 运营对齐 |
| 06-15 14:00 | 配置覆盖：上海、江苏、浙江、安徽 |
| 06-16 | 切灰度 10%，观察 3 天 |
| 06-19 | 切全量，华东跨区占比从 38% 降至 6% |

---

## 5. 改进措施

| 措施 | 类型 | 状态 |
|------|------|------|
| **新仓上线 Checklist** 增加「路由配置完成」强制项 | 流程 | ✅ |
| 健康巡检「有库存未配路由」自动告警 | 产品 | ✅ 已上线 |
| WMS 新仓创建时，路由状态默认「未启用」+ 弹窗提醒配置 | 产品 | ✅ |
| 运营后台首页展示「待配置路由的新仓」Banner | 产品 | 🔄 V1.1 |
| 每月仓储规划复盘会过一遍路由健康报告 | 管理 | ✅ |

---

## 6. 经验沉淀

### 核心教训
> **有能力 ≠ 被使用。** 上海仓能发货，但不在路由候选池，等于不存在。

### 产品设计启示
1. **默认安全（未启用）+ 主动提醒（健康巡检）** 的组合是对的，但 Checklist 要更早介入
2. 告警要 actionable——「去配置上海仓」一键跳转，降低处置摩擦
3. PM 要盯的不只是功能上线，还有**功能被正确使用的运营闭环**

### 面试话术
> 「上海仓上线 56 天没配路由，华东订单全跨区发。根因是新仓 SOP 缺路由配置卡点。我们加了健康巡检自动发现 + 新仓 Checklist，配完后华东跨区从 38% 降到 6%。这个 Case 让我理解：产品交付的是能力，运营闭环才是价值。」
