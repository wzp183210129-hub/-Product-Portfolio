## 一、指标设计原则

1. **不看单一准确率**——90% 准确但 10% 错在赔偿场景，业务伤害更大
2. **分三层对齐不同角色**——算法看模型、PM 看产品、老板看业务
3. **北极星指标要有业务语义**——不是「AI 回复率」，而是「用户真的被解决了没」

---

## 二、北极星指标

### 有效 AI 解决率（Effective AI Resolution Rate）

```
有效 AI 解决率 = AI 自动回复会话数中，同时满足以下条件的占比：

  ① 用户未点踩该条 AI 回答
  ② 用户未在该会话中主动转人工
  ③ 用户 24 小时内未就同一意图重复发起咨询
```

| 维度 | 说明 |
|------|------|
| 为什么选它 | 同时衡量 AI「答了」和 user「满意/被解决」 |
| V1.0 目标 | ≥ 55%（上线 3 个月） |
| 观察频率 | 日看趋势，周看分布 |
| 告警阈值 | 连续 3 天下降 >5pp → 触发 Bad Case 专项复盘 |

## 四、模型层指标

| 指标 | 定义 | V1.0 目标 | 采集方式 |
|------|------|-----------|----------|
| 检索命中率 | Top-K 检索结果中包含正确 doc 的占比 | ≥ 85% | Golden Set 50 条周测 |
| 引用准确率 | AI 回答中的引用与 doc 内容一致 | ≥ 90% | 人工抽检 100 条/周 |
| 意图识别准确率 | 意图分类与标注一致 | ≥ 88% | Golden Set |
| P95 响应延迟（Case A） | 从用户发送到 AI 回复 | ≤ 4s | APM 埋点 |
| P95 审核推送延迟（Case B） | 从用户发送到 B 端可见 | ≤ 5s | APM 埋点 |
| 幻觉率 | 回答内容与知识库/ API 矛盾 | ≤ 3% | Bad Case 标注 |

**必埋字段（数据验收）：**

```
session_id, message_id, confidence, citations[],
model_name, latency_ms, case_type(A/B/C),
intent, tenant_id
```

## 五、产品层指标（PM 日常盯）

| 指标 | 定义 | V1.0 目标 | 动作阈值 |
|------|------|-----------|----------|
| **AI 直接解决率** | Case A 会话 / 总会话 | ≥ 60% | <50% → 查知识库覆盖 |
| **转人工率** | 转人工会话 / 总会话 | ≤ 35% | >45% → 查阈值是否过紧或知识缺失 |
| **点踩率** | 被点踩 AI 消息 / AI 消息总数 | ≤ 8% | >12% → 触发 Bad Case 复盘 |
| **客服采纳率** | 确认发送或轻微修改 / 审核队列总数 | ≥ 70% | <50% → 改 Prompt 或话术库 |
| **客服改写率** | 大幅修改或拒绝 AI 建议 / 审核队列总数 | ≤ 25% | >40% → AI 建议不可用 |
| **Case 分布** | A:B:C 占比 | 60:25:15（参考） | C>25% → 知识库或意图模型问题 |
| **重复咨询率** | 24h 内同 intent 再次咨询 / 总会话 | ≤ 12% | >18% → 一次解决率有问题 |

### 分场景监控（重点场景专项）

| 场景 | 额外指标 | 告警 |
|------|----------|------|
| 物流查询 | 物流类点踩率 | >10% |
| 质量投诉 | Case B 审核 SLA 达标率 | <90% |
| 历史承诺/投诉 | Case C 摘要完整率 | <80% |

## 七、上线后看数节奏

### 第一周（验证期）

| 天 | 动作 |
|----|------|
| D+1 | 确认埋点完整率 100%；Case A/B/C 分流是否符合预期 |
| D+2 | 拉 Top 10 转人工原因 + Top 10 点踩 |
| D+3 | 客服访谈：审核队列好不好用？推荐话术采纳吗？ |
| D+5 | 首次 Bad Case 复盘会 |
| D+7 | 周报：有效 AI 解决率、Case 分布、P95 延迟 |

### 第一月（调优期）

| 周 | 动作 |
|----|------|
| W1 | 阈值校准：根据 Bad Case 分布调整 0.85/0.60 |
| W2 | 知识库补洞：Top 20 知识缺失问题入库 |
| W3 | 话术优化：改写率最高场景改 Prompt |
| W4 | 月度复盘：业务层指标初评 + V1.1 需求清单 |

## 九、指标与 Bad Case 的联动

```
点踩率上升
  → 下钻 Top 点踩场景
    → 根因分类（K/R/B/G/D/P）
      → 知识缺失 → 补知识库
      → 检索错误 → 调 chunk / embedding
      → 边界错误 → 调阈值 / 改流程
      → 数据源问题 → 工程修复
      → 话术问题 → 改 Prompt
```

## 十、面试话术（如何讲指标）

> 我不只用「准确率」评估 AI 客服。准确率 90% 但错在赔偿场景，业务风险远大于 70% 准确但稳态转人工。
>
> 我定义的北极星是 **有效 AI 解决率**——AI 答了，用户没点踩、没转人工、没重复问。
>
> 上线第一周我不追求数字好看，而是盯 **Top 转人工原因** 和 **客服改写率**——前者告诉我知识库缺什么，后者告诉我 AI 建议能不能用。
